### 1.1 발견별 근거와 수정안

#### 1. 리더의 수직 기동(1.3 m 이상 상승·하강)이 수직 FOV 이탈 → 소실 → 10 s 뒤 FAILSAFE_LAND 로 이어진다 (MAX_VZ 0.12 + 출발 판정이 수평속도만 봄)

## 2. 우선순위 제안

신규 21건과 남은 57건을 합쳐 '첫 실비행 전에 반드시' / '첫 비행 뒤 다음 단계' 로 나눈 제안이다. 선택은 사용자의 몫이다.

**첫 실비행 전 (코드 수정 작음, 효과 큼)** — 2026-10-01 같은 날 전부 적용했다(VERIFICATION.md 「첫 비행 전 7가지」).

1. 출발·호버 판정에 수직 속도를 포함하고 MAX_VZ 를 수직 추종이 되는 값으로 올린다(신규 1). 지금은 리더가 1.3 m 만 오르내려도 10 s 뒤 자동 착륙이다.
2. 트랙 폐기 뒤 재획득을 '가장 큰 물체' 가 아니라 EKF 예측점 근처 검출로 하고, 3-D 게이트가 거부한 측정의 bearing 은 쓰지 않는다(신규 2). 리더가 보이는데도 다른 물체로 넘어가는 경로다.
3. MIN_AGL_M 바닥을 fail-closed 로: LOCAL_POSITION_NED 가 낡으면 하강 명령 금지(이전 #7). 한 줄이다.
4. 'v'(송신 토글)·'l'(수동 LAND) 키에 GUIDED 진입 리셋과 조종사 우선 게이트를 적용한다(신규 3·11). 조작 실수 한 번이 LAND 가 된다.
5. ATTITUDE yaw 불연속 검사(한 샘플에 0.3 rad 이상이면 보상 생략)와 ESP32 패킷 속도 누락 처리(신규 5·9).
6. FC 파라미터를 README 에 필수 항목으로 적고 시동 전 체크리스트로 만든다(4절). 배터리·펜스·RC failsafe 는 컴패니언이 아니라 FC 가 지켜야 한다(신규 7·20·21).
7. 벽시계 대신 `time.monotonic()` 을 쓴다(이전 #48·#49). NTP 점프 한 번이 LAND 또는 송신 정지가 된다.

**첫 비행 뒤 다음 단계**

- 소실 10 s 뒤 자동 LAND 를 유지할지 외부 관례(HOLD + 조종사/FC failsafe)로 바꿀지 결정하고 `lost_action` 설정으로 노출(신규 6).
- 카메라·FC 예외 시 setpoint 송신·미션 갱신이 끊기는 continue/break 구조, 프로세스 종료 시 무한 호버(이전 #1·#8·#53), 컴패니언 heartbeat 와 sysid(이전 #14·#50).
- 신뢰도가 R 과 게이트를 함께 넓히는 구조(이전 #26·#59, 신규 16): 게이트는 기본 R 로, 신뢰도는 칼만 이득에만.
- 기울어진 기체 프레임 레벨링과 카메라 마운트 자세(이전 #2·#22·#42), GPS 단독 추종의 수직축 2D 화(신규 8).

## 4. 실비행 전 FC 파라미터 (ArduPilot 소스 대조 결과)

- `GUID_TIMEOUT` 3.0 유지(0.1~5). 컴패니언 10 Hz(실측 9.1~9.2 Hz, 최대 갭 0.14 s) 대비 충분. 더 짧게 하면 카메라 스톨 한 번에 정지/재출발을 반복한다.
- `WP_YAW_BEHAVIOR` 0. yaw 는 RATE 로 직접 주므로 영향은 GUID_TIMEOUT 뒤 HOLD 뿐이지만 README·하네스와 통일.
- `GUID_OPTIONS` bit2(IgnorePilotYaw)=4 권장 — 조종사 yaw 스틱이 10 Hz RATE 재설정과 싸워 떨림만 만든다(위). bit0(송신기 시동 허용)은 끈 채로.
- `FS_THR_ENABLE` 1(RTL) 또는 5(LAND) 유지, `FS_OPTIONS` bit2 'Continue if in Guided on RC failsafe' 는 **끄기** — 켜면 RC 가 끊겨도 GUIDED 가 유지돼 조종사 탈환 수단이 사라진다(events.cpp:66-69).
- `FS_GCS_ENABLE`: 컴패니언이 heartbeat 를 안 보내므로 이 값은 실제 GCS 링크에만 작용한다. 켤 경우(1 RTL / 5 LAND) GCS 끊김 → RTL 로 자동 추종이 끝난다는 점을 운용 절차에 반영. `MAV_GCS_SYSID` 는 255 유지(컴패니언 명령이 sysid 255 라 enforce 옵션을 켜도 통과; 바꾸면 컴패니언 명령 전부 묵살).
- `FS_EKF_ACTION` 1(LAND) 유지. 2(ALT_HOLD) 는 조종사 즉시 개입 전제.
- `FENCE_ENABLE` 1, `FENCE_TYPE` 7(고도+원+다각형), `FENCE_ACTION` 1(RTL) 또는 4(Brake/Land), `FENCE_ALT_MAX`·`FENCE_RADIUS` 는 시험장 기준 — 리더 오인·외삽 추종으로 멀어지는 사고의 마지막 방어(이전 감사 '최대 거리 없음' 항목의 운용측 보완).
- `BATT_FS_LOW_ACT`/`BATT_FS_CRT_ACT` 2(RTL)/1(LAND), `BATT_LOW_VOLT` 설정 — 컴패니언은 배터리를 보지 않는다.
- `SYSID_THISMAV` 팔로워 1 / 리더 2 로 분리(1절 15번), `SERIALn_PROTOCOL` 2(MAVLink2), 컴패니언 포트 `SRn_*` 는 request_data_streams 가 덮는다.
- `DISARM_DELAY` 기본 10 s — GUIDED 지상 아이들(1절 13번) 뒤 자동 시동해제가 되는 이유.
- PX4 운용 시: `COM_OF_LOSS_T` 1.0 유지, `COM_OBL_RC_ACT` 기본 0(Position) 은 조종사 즉시 개입 전제이며 무인 운용이면 5(Land)/6(Hold) 검토; `NAV_RCL_ACT` 2(Return) 유지; `MAV_x_MODE` 를 Onboard 로 해 LOCAL_POSITION_NED 가 10 Hz 이상 나오게(이전 감사 critical 항목).

### 4.1 소스로 확정한 FC 동작

**type_mask 1479 + MAV_FRAME_BODY_NED (ArduCopter, ap_GCS_MAVLink_Copter.cpp:968-1077)**
- 1479 = X|Y|Z(7) + AX|AY|AZ(448) + YAW(1024); VX/VY/VZ, YAW_RATE 비트 clear (fc_iface_repro.py mask 로 확인). pos_ignore && !vel_ignore → `set_vel_accel_NED_m(vel, accel=0, use_yaw=false, use_yaw_rate=true, yaw_rate)`.
- BODY_NED 는 **yaw 만** 돌린다: `vel_ned_ms.xy() = ahrs.body_to_earth2D(vel.xy())` (1037-1039행), z 는 그대로 지구 하방. roll/pitch 는 돌리지 않는다 (이전 감사 'vz 지구 하방' 항목과 일치). PX4 도 동일: mavlink_receiver.cpp:1266-1270 (yaw 만 회전, vz 그대로). PX4 는 VX/VY/VZ 중 **하나라도** ignore 면 속도 전체를 NaN 으로 만든다(1255-1256) — 현재 마스크는 셋 다 clear 라 문제없음.
- yaw 비트 set + yaw_rate 비트 clear → `set_yaw_state_rad(false, _, true, rate)` → `auto_yaw.set_rate_rad(rate)` = AutoYaw RATE 모드(ap_mode_guided.cpp:1055-1056). rate=0 이면 heading_mode Rate_Only 로 현재 기수 유지 — '현재 기수 유지' 해석 맞음. GUID_TIMEOUT 뒤 RATE → HOLD (851-853행).
- 조종사 yaw 스틱: `AutoYaw::get_heading()` 이 `use_pilot_yaw()`(GUID_OPTIONS bit2 IgnorePilotYaw 꺼져 있으면 참) 일 때 스틱 입력이 있으면 PILOT_RATE 로 바꾸지만(ap_autoyaw.cpp:358-363) 다음 setpoint(≤100 ms)가 다시 RATE 로 덮는다 → GUIDED 중 조종사 yaw 스틱은 사실상 무효·떨림. 탈환은 모드 스위치로만 가능. 결함이 아니라 운용 사실.
- NaN/inf 속도는 FC 가 `hold_position()` (1031-1035행) — 컴패니언 쪽 방어(send_body_velocity)와 이중.

**GUID_TIMEOUT (기본 3.0 s, ap_Parameters.cpp:861-867)**: velaccel_control_run 이 속도·가속 목표를 0 으로 (849-850행) → 위치제어기가 감속 후 그 자리·그 고도에서 호버. 착륙 아님. yaw RATE → HOLD. 즉 컴패니언이 죽으면 '무한 호버' (이전 감사 항목).

**LAND 뒤 setpoint**: 수신 핸들러 첫 줄 `if (!copter.flightmode->in_guided_mode()) return;` (975-977행) — LAND 에서는 무시. 우리가 LAND 뒤 setpoint 를 안 보내는 것은 맞고, 보내도 무해.

**set_mode / send_land**: pymavlink `set_mode()` 는 `self.field('HEARTBEAT','autopilot')` = **마지막으로 받은 HEARTBEAT 의 발신자** 로 PX4/APM 을 고르고(mavutil.py:679-685), `mode_mapping()` 은 `sysid_state[self.sysid].mav_type` (636-644) 을 쓴다. 둘 다 is_fc_heartbeat 와 무관한 pymavlink 내부 상태라 같은 sysid 의 다른 기체형 heartbeat(MAV_TYPE_CAMERA 등; probably_vehicle_heartbeat 는 GCS/GIMBAL/ADSB/ONBOARD_CONTROLLER 만 제외, 356-368행) 가 섞이면 mode_mapping 이 None 이 되어 set_mode 가 False → COMMAND_LONG NAV_LAND 폴백. 다행히 ArduCopter(ap_GCS_MAVLink_Copter.cpp:534-538)와 PX4(Commander.cpp:1236) 모두 NAV_LAND 를 LAND 모드 전환으로 처리하므로 폴백은 살아 있다. 확신이 낮아 findings 에서 제외.

**sysid 255 / compid 0 과 GCS failsafe**: ArduCopter GCS failsafe 타이머는 `sysid_is_gcs(msg.sysid)` 인 발신자의 **HEARTBEAT / MANUAL_CONTROL / RC_CHANNELS_OVERRIDE** 로만 갱신된다(GCS_Common.cpp:4380-4386, 7755-7768; events.cpp:126-160 'only looks at the heartbeat'). 컴패니언은 HEARTBEAT 를 보내지 않으므로 FS_GCS_ENABLE 을 켜도 컴패니언 생사와는 무관하고, 오직 실제 GCS(sysid 255) 링크로만 발동한다. 반대로 컴패니언이 나중에 heartbeat 를 보내게 고치면 sysid 255 라서 실제 GCS 가 끊겨도 FS_GCS 가 안 울린다 — heartbeat 를 추가할 때는 sysid 를 1(기체)+compid 191(MAV_COMP_ID_ONBOARD_COMPUTER) 로 바꿔야 한다.

**PX4**: OFFBOARD 진입은 offboard_control_mode 가 COM_OF_LOSS_T(1.0 s) 안에 publish 되어야 하고 setpoint 는 `accepts_offboard_setpoints` 일 때만 trajectory 로 나간다(mavlink_receiver.cpp:1307-1328). 손실 시 COM_OBL_RC_ACT=0 기본 = Position(수동) 모드로 폴백(failsafe.cpp:264-273, 773-782); RC 도 없으면 manual control loss 폴백 → NAV_RCL_ACT=2(Return). 즉 PX4 에서 컴패니언이 죽으면 ArduCopter 와 달리 **1 s 뒤 조종사에게 넘어간다** — 조종사가 즉시 받을 준비가 돼 있어야 한다. 'v' 키로 송신을 끄는 것도 같은 효과. yaw=NaN + yawspeed=0 일 때 PX4 의 기수 유지 동작은 저장된 소스로 확인 못 함(재현 안 함).

**is_fc_heartbeat 컴포넌트 고정**: 첫 기체형 heartbeat 의 comp 로 고정 — ArduPilot/PX4 모두 comp 1 이라 정상. pymavlink 이 버전은 target_component 를 param_sysid[1] 로 두고 heartbeat 로 갱신하지 않는다(mavutil.py:219-238) → 고정 전 setpoint 는 comp 0(브로드캐스트)으로 나가며 ArduPilot 라우팅은 이를 로컬 처리한다. 문제 없음.

**drain_messages 필터 결과**: EKF_STATUS_REPORT·BATTERY_STATUS 는 EXTRA3 스트림이라 request_data_streams(POSITION/EXTRA1/EXTENDED_STATUS) 로는 오지 않는다 — 배터리는 SYS_STATUS 로만 보이고 EKF 분산·센서 건강 비트는 전혀 보지 않는다(이전 감사 항목). FC 가 스스로 LAND/RTL 로 바꾸면(EKF failsafe ap_ekf_check.cpp:166-216, 배터리, FS_GCS, 펜스) 컴패니언은 '조종사 탈환' 으로 보고 setpoint 만 계속 흘린다(FC 가 무시) — 결과적으로 안전한 방향이며 추가 결함은 없다. 다만 FS_EKF_ACTION=2(ALT_HOLD) 는 스틱 중립 호버로 떨어뜨리므로 조종사가 즉시 받아야 한다.

**time_boot_ms / MAVLink2**: 이전 감사 항목 그대로. pymavlink 는 FC 가 MAVLink2 STX(253) 를 보내면 자동 전환(mavutil.py:284-298) — ArduPilot SERIALn_PROTOCOL=2 면 alt_ellipsoid/h_acc 가 들어온다.

**하네스 가정 (sitl/harness.py)**: preflight 가 main 보다 먼저 NAV_TAKEOFF 를 끝내므로 finding 2(이륙 중단)는 하네스에서 드러나지 않는다. 조종사 링크도 sysid 255/comp 0 이라 컴패니언과 같은 신원이지만 채널이 달라 ArduPilot 라우팅이 (255,0) 경로를 마지막 채널로 갱신할 뿐 응답(ACK)은 수신 채널로 가므로 무해. `--wp-yaw-behavior 0` 기본이라 C5 검사는 README 권장값 기준이다.

**지상에서의 부작용(결함 아님)**: FC 가 GUIDED·시동해제 상태로 지상에 있을 때 리더를 잠깐 보고 10 s 잃으면 FAILSAFE_LAND → LAND 모드 전환이 나가고, LAND 는 시동을 허용하지 않아(ModeLand::allows_arming false) 조종사가 모드를 바꿔야 시동이 된다. GUIDED 는 송신기 시동도 GUID_OPTIONS bit0 없이는 거부(ap_mode_guided.cpp:118-127) — README 의 'ALT_HOLD 수동 이륙' 절차와 일치.
