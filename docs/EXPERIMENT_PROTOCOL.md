# 실험 프로토콜 — AST 투고용 비행 캠페인 (2026-09-24)

목표는 하나입니다. **선형 해석(docs/STABILITY_MARGINS.md, FORMATION_THEORY.md)이 실제 기체에서 닫힌다는 것을 독립 계측으로 보이는 것.**
그러려면 세 가지 숫자가 실기에서 나와야 합니다: 식별된 플랜트(τ, L), 정현파 시험의 |Γ(jω)| 실측점, 추정기 일관성(NIS/NEES).
이 문서는 그 숫자를 첫 비행 날부터 뽑을 수 있게 장비·교정·비행 카드·분석 명령을 정해 둡니다. 안전 절차는
[FLIGHT_SAFETY_CHECKLIST.md](FLIGHT_SAFETY_CHECKLIST.md) 가 우선이고 여기서는 반복하지 않습니다.

```bash
python3 analysis/identify_plant.py --selftest && python3 analysis/sine_gain.py --selftest && python3 analysis/nees_nis.py --selftest
python3 test_closed_loop.py --scenario sine --log-dir /tmp/sine   # 실제 코드 폐루프 로그로 세 도구를 검증 (3자 일치)
```

## 1. AST 기준으로 어디에 힘을 주고 어디를 빼는가

AST(Aerospace Science and Technology) 의 편대·추종 논문들(예: 다중 리더 고정익 편대 추종, 암묵적 리더 스웜 편대, 경로 구동
편대-포함 제어)은 **모델 → 제어 법칙 → 안정성 증명(Lyapunov 또는 주파수 영역) → 시뮬레이션** 이 뼈대이고, 실비행은 있으면 차별점이지
필수는 아닙니다. 심사평이 몰리는 곳은 "모델은 어디서 왔나", "증명이 정리-증명 형식인가", "외란(바람)에 어떻게 되나", "무엇과 비교했나"
입니다. 비전 추종 논문은 이 저널에서 드물고 로봇 저널(RA-L, JINT) 쪽에 많으므로, 우리 원고는 **제어 논문의 틀에 비전을 얹은 것**으로 써야
합니다. (초록·검색 결과 수준의 조사입니다. 전문은 이 환경에서 못 읽었습니다.)

| 힘을 줄 곳 | 지금 | 해야 할 것 |
|---|---|---|
| **플랜트 식별** | τ_fc = 0.3 s 가정 | E1 로 K·τ·L 실측, `identify_plant.py --margins` 로 여유 재계산. 원고의 표 1 |
| **정리-증명 형식** | 정리 1~3 은 있음 | 가정(A1~A4)·정리·증명·따름정리로 다시 쓰고, 식별된 τ·L 의 불확실성 구간에서 강건성(τ 0.2~1.2 s 스윕)을 그림으로 |
| **실측 |Γ|** | SITL 0.72 | E3 에서 ω 2~3 개 × 10 회. 선형 곡선 위에 실측점 ± 표준편차 |
| **외란(바람)** | 수평화·자세 보정 논리만 | E7: 풍속 기록 + 호버·추종 RMS. "바람 3 m/s 에서 간격 RMS x m" 문장 하나가 심사평 하나를 막는다 |
| **비교 기준선** | 시뮬에서만 | B1(P+D 만), B2(지연 정합 없는 옛 FF) 를 실기에서 같은 시험으로. B3(ArduPilot Follow) 는 되면 좋고 안 되면 뺀다 |
| **통계** | 없음 | 조건당 N = 10, 평균 ± 표준편차, 표로 |

| 힘을 뺄 곳 | 이유 | 처리 |
|---|---|---|
| YOLO·트래커·스케줄러 상세 | AST 심사진의 관심 밖, 새 것도 아님 | 시스템 절에 반 쪽. 최근접 깊이 무리는 한 문단(왜 필요한지 + E5 결과) |
| 안전 검증 방법론(차등 검증, 하네스, 위험 분석) | 좋은 공학이지만 논문 기여가 아님 | 부록 A 한 쪽 또는 "재현성" 문단. 별도 논문감 |
| 편대(다기체) | 실험이 없음 | 해석 절 끝의 따름정리 + 향후 과제. 제목·초록에 넣지 말 것 |
| 자율 착륙·미션 상태머신 | 운용 논리 | 시스템 절 한 문단 |
| 시간간격 정책(정리 2) | 실험 없음 | 각주 수준 |

**빠지면 안 되는 문장 세 개.** (1) "플랜트는 비행 데이터로 식별했다(표 1)." (2) "실측 |Γ| 은 예측과 ±x % 안에서 일치한다(그림 n)." (3) "추정기
공분산은 NIS/NEES 로 일관함을 확인했다(그림 m)." 이 셋이 없으면 시뮬레이션 논문으로 읽힙니다.

## 2. 장비 — UWB 거리 GT (총 20만 원 이하)

RTK 대신 **UWB 양방향 거리측정(TWR)** 으로 선두↔후미 거리를 잽니다. 거리 한 축뿐이지만, 논문 주장(스트링 안정성·간격 오차)이 모두
전진축이라 핵심은 살고, 측면·고도는 추정값과 공분산으로만 보고합니다(한계로 명시).

| 품목 | 수량 | 역할 |
|---|---|---|
| Makerfabs ESP32 UWB DW3000 (약 44 달러) | 3 (예비 1) | 후미: initiator(거리 계산·시리얼 출력). 선두: responder |
| USB 케이블·5 V 보조배터리 | 각 1 | 선두 responder 전원 (사람 리더는 보조배터리, 드론 리더는 5 V BEC) |
| 줄자 30 m, 삼각대, 콘 6개 | | 정적 교정·계단 시험 거리 표시 |

**연결.** 후미 initiator 를 Jetson USB 에 꽂고(`/dev/ttyUSB1`, 환경변수 `MARS_UWB_PORT`), 펌웨어가 거리를 한 줄씩 찍게 합니다. 줄 형식은
`{"range": 3.12, "seq": 17}` 이 가장 좋고, `3.12`, `312 cm`, `Range: 3.12 m` 도 받습니다(`uwb_reader.parse_uwb_line`). 10 Hz 이상.
Makerfabs 저장소의 DW3000 TWR 예제(initiator/responder)에서 `Serial.print` 줄만 JSON 으로 바꾸면 됩니다. 선두 ESP32 가 이미
텔레메트리 JSON 을 보낸다면 거기에 `"uwb_range"` 를 실어도 됩니다(`config.uwb.kind = "leader_packet"`) — 단 이 방식은 GT 가 ESP-NOW
링크에 묶이므로 권장은 후미 시리얼입니다.

**기하(선두를 감안).** 모듈 안테나는 카메라 원점도, 선두의 시각 중심(bbox 중심)도 아닙니다. 줄자로 재서 적습니다.

| 설정 | 뜻 | 사람 리더 예 | 드론 리더 예 |
|---|---|---|---|
| `uwb.anchor_offset_fru` | 후미 안테나 − 카메라 원점 (후미 FRU, m) | [0.05, 0.08, −0.02] | 동일 |
| `uwb.tag_offset_leader_fru` | 선두 태그 − 선두 시각 중심 (선두 FRU, m) | 가슴 높이 태그, bbox 중심 ≈ 배꼽: [0.05, 0, +0.25] | 상판 태그: [0, 0, +0.06] |
| `uwb.bias_m` | 정적 교정 바이어스 | 3절에서 | 3절에서 |

보정식은 `uwb_reader.uwb_range_to_center`: r² = |ρ u + (t − a)|² 를 EKF 시선 단위벡터 u 로 풀어 ρ = 카메라 원점↔시각 중심 거리를 얻습니다.
오프셋이 시선에 직교하면 보정은 2차(3 m 에서 0.25 m 오프셋 → 1 cm)라 대충 재도 되지만, 시선 방향 성분(태그가 앞/뒤에 있음)은 1차로
그대로 들어가므로 정확히 잽니다. 상대 heading 을 알면(방송 yaw) 선두 프레임 오프셋을 돌려 쓰고, 모르면 시선과 나란하다고 봅니다.

**제어에는 절대 쓰지 않습니다.** 코드가 `uwb.*` 로그 블록과 STAT 표시 외에는 값을 만지지 않는다는 것을 단위 검사가 지킵니다.

## 3. 정적 교정 (비행 전날, 30 분)

1. 후미 기체를 삼각대 높이(1.2 m)에 두고 카메라·UWB 를 켠다 (`SEND_MAVLINK_COMMANDS=False`, 프로펠러 없음).
2. 선두(사람 또는 드론)를 줄자로 **2 / 3 / 5 / 8 / 10 m** 정면에 세우고 각 30 s 기록. 시야에 다른 사람 없음.
3. 같은 자리에서 리더 가리개(사람 한 명)를 시선 중간에 두고 10 s 씩 — NLOS 편향 확인.
4. 로그에서 `uwb.range_center_m` 의 평균−줄자 = 바이어스, 표준편차 = σ. `measurement.depth_m` 도 같은 표로(카메라 깊이의 거리별 바이어스·σ,
   원고 표 2). 바이어스는 `config.uwb.bias_m` 에, σ 는 `nees_nis.py --uwb-sigma` 에.
5. 합격: σ ≤ 0.10 m, 거리별 바이어스 변화 ≤ 0.05 m. 아니면 안테나 방향·전원 잡음·오프셋 재측정.

한 줄 확인: `python3 analysis/nees_nis.py --log logs/<정적>.jsonl --uwb-sigma <σ>` 의 "잔차 bias/σ" 가 곧 표 2 의 행입니다.

## 5. 실험 카드

공통: 조건당 **10 회**, 각 회 40~60 s, 리더는 팔로워 정면 3~4 m 에서 시작, 바람 ≤ 5 m/s, 시야에 리더만. 각 카드의 "분석" 명령이 표·그림의
원천이고, 결과 JSON 은 `docs/results/<실험>/` 에 모읍니다.

## 7. 판단 기준 (go / no-go)

| 질문 | 기준 | 못 넘으면 |
|---|---|---|
| 식별이 됐나 | 3 축 fit > 80 %, 회차 간 τ ±30 % | 진폭 0.4, 계단 6 s 로 재시험 |
| 해석이 닫히나 | 두 ω 이상에서 실측/예측 0.85~1.15 | 식별값으로 여유 재계산 뒤 이득 조정, 원고는 "재설계" 이야기로 |
| 추정기가 정직한가 | NIS 평균이 95 % 구간 안 또는 그 이유(R 과대/과소)가 설명됨 | `config.reliability.base_R_*` 재조정 뒤 재비행 |
| 통계 | 조건당 N ≥ 10 | 비행 날 추가 |

## 8. 이 도구들의 검증

- 자체검사: `identify_plant.py --selftest`(K 0.97·τ 0.35·L 0.12 되찾음, fit 88 %), `sine_gain.py --selftest`(이득 0.7·위상 −35° 를 esp32/uwb/ekf
  세 출처에서), `nees_nis.py --selftest`(일관/과신 판별). 단위 검사 `논문 도구:` 로 회귀.
- 3자 일치: `test_closed_loop.py --scenario sine --log-dir <dir>` 가 실제 코드를 가짜 FC 로 비행시켜 로그와 가짜 UWB 를 남기고, 그 로그에서
  `sine_gain`(uwb) 이 |Γ| 0.699 ± 0.025 @ −132° 를 얻어 선형 모델 0.669 @ −131° 와 4 % 안에서 맞고, `identify_plant` 가 가짜 FC 의
  τ 0.3 s 를 fit 99.6 % 로 되찾으며, `nees_nis` 가 잡음 없는 가짜 세계를 "과소신뢰" 로 옳게 판정한다.
- 한계: UWB 모듈·펌웨어는 실기 미검증(3절 정적 교정이 첫 확인). `--leader ekf` 는 참고용.
